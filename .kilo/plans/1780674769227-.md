# Mobile Calendar UX Redesign Plan

## Problem
On mobile (< 768 px), the full month calendar grid renders with 7 columns. Event cards are shrunk to `0.7rem` font, cells are only `80px` min-height, and the entire experience is cramped and hard to use. Users cannot easily read show details or tap the correct event.

## Goal
Replace the mobile month-grid with a **week-centric** view that is readable, touch-friendly, and fast to navigate.

---

## Proposed UX (refined from user request)

Instead of literal "tabs" (which are hard to fit 7 of across a narrow screen), use a **modern week-strip + day-detail** pattern similar to iOS Calendar and Google Calendar mobile:

1. **Week navigation bar** at the top  
   `◀  1 – 7 Jun 2026  ▶`  
   Tapping arrows shifts by one week. The range text is also tappable to jump to "Today".

2. **Day strip** (Mon–Sun) below the nav bar  
   Seven compact day-pills in a row. Each shows:
   - Day initial (`M`, `T`, `W`, `T`, `F`, `S`, `S`)
   - Date number (`2`, `3` …)
   - **Event dot** (small coloured dot if that day has ≥1 show)
   - **Today ring** (highlighted circle for the current date)
   - **Selected state** (filled periwinkle background when tapped)

3. **Event list** for the selected day  
   Full-width, vertically scrollable cards using the existing `event-card-green` / `event-card-peach` styles. Each card shows:
   - Program name (full size, not shrunk)
   - Venue
   - FOH / Stage crew (with icons)
   - Tapping a card opens the existing event detail modal (reuse `openEventModal`)

4. **Empty state**  
   If the selected day has no shows, display a friendly "No shows on [Day]" message with an illustration or icon.

---

## Why this is better than literal tabs

- **7 literal tabs** across 320–400 px width = ~45 px per tab. Labels get truncated and touch targets become error-prone.
- **Day strip pills** (circles/rounded squares) are a proven mobile pattern; users instantly recognise them from every calendar app.
- **One-tap context switch**: user sees the whole week at a glance and can jump to any day in a single tap.

## Files to modify

| File | What changes |
|---|---|
| `src/index.tsx` | Add a `#mobileCalendarView` container (hidden on `md:` and up) inside the existing `#calendarView`. Add supporting CSS for the day-strip, week-nav, and mobile event list. |
| `public/static/app.js` | Add `renderMobileCalendar()`, `renderMobileWeekStrip()`, `renderMobileDayEvents()` functions. Detect mobile viewport on init and call mobile renderer instead of `renderCalendar()`. Wire prev/next week buttons and day-pill clicks. |

---

## State changes

- Reuse `currentDate` (already tracks the month being viewed).
- Add `selectedMobileDate` (Date object, defaults to today) — the specific day whose events are shown.
- When on mobile:
  - `currentDate` determines which **week** is displayed.
  - `selectedMobileDate` determines which **day** is active in the strip and whose events are listed.
- Changing week via arrows keeps `selectedMobileDate` aligned to the same day-of-week if possible, or snaps to the first day of the new week.

## Detailed implementation steps

### 1. HTML / CSS — `src/index.tsx`

Inside `#calendarView`, add a new sibling container:

```html
<!-- Mobile week view (hidden on desktop) -->
<div id="mobileCalendarView" class="md:hidden">
  <!-- Week nav -->
  <div class="flex justify-between items-center mb-3 px-1">
    <button id="mobilePrevWeek" class="btn-glass px-3 py-1.5 text-sm"><i class="fas fa-chevron-left"></i></button>
    <span id="mobileWeekLabel" class="text-sm font-semibold text-gray-700">1 – 7 Jun 2026</span>
    <button id="mobileNextWeek" class="btn-glass px-3 py-1.5 text-sm"><i class="fas fa-chevron-right"></i></button>
  </div>
  <!-- Day strip -->
  <div id="mobileDayStrip" class="flex justify-between mb-4 gap-1"></div>
  <!-- Day events -->
  <div id="mobileDayEvents" class="space-y-3 pb-6"></div>
</div>
```

Add CSS classes (inside the existing `<style>` block):
- `.mobile-day-pill` — flex column, centred, rounded-xl, min-width/touch-target `48px`, padding `8px 4px`.
- `.mobile-day-pill.selected` — filled periwinkle background `#98A2D7`, white text.
- `.mobile-day-pill.today` — ring outline in periwinkle.
- `.mobile-event-dot` — `6px` circle, green if requirements+time ready, peach otherwise.
- `.mobile-event-card` — reuses `.event-card-green`/`.event-card-peach` but at full readable size (`text-sm` or `base`).

Hide the desktop grid `#calendarGrid` and its sticky header on mobile via the existing `@media (max-width: 767px)` block or Tailwind `hidden md:grid`.

### 2. JavaScript — `public/static/app.js`

#### 2a. Detect mobile
Add a helper:
```js
function isMobileView() {
  return window.innerWidth < 768;
}
```
In `renderCurrentView()`:
```js
if (currentView === 'calendar') {
  if (isMobileView()) renderMobileCalendar();
  else renderCalendar();
}
```
Add a `resize` listener that switches between desktop and mobile renderers when crossing the 768 px breakpoint.

#### 2b. Week math helpers
```js
function getWeekStart(date) {
  const d = new Date(date);
  const day = d.getDay(); // 0 = Sun
  const diff = d.getDate() - day + (day === 0 ? -6 : 1); // Monday start
  return new Date(d.setDate(diff));
}
function getWeekEnd(weekStart) {
  const end = new Date(weekStart);
  end.setDate(end.getDate() + 6);
  return end;
}
```

#### 2c. `renderMobileCalendar()`
1. Compute `weekStart` from `currentDate` using `getWeekStart()`.
2. Update `#mobileWeekLabel` with formatted range (e.g. "1 – 7 Jun 2026").
3. Call `renderMobileWeekStrip(weekStart)`.
4. Call `renderMobileDayEvents(selectedMobileDate)`.

#### 2d. `renderMobileWeekStrip(weekStart)`
1. Clear `#mobileDayStrip`.
2. Loop 0–6:
   - `dayDate = new Date(weekStart); dayDate.setDate(weekStart.getDate() + i)`
   - Build a pill element: day initial + date number + optional event dot.
   - Event dot colour: if any event on that date has `requirements_updated && call_time` → green dot, else peach dot.
   - Add `.selected` if `dayDate` matches `selectedMobileDate`.
   - Add `.today` if `dayDate` is today.
   - `onclick` → set `selectedMobileDate = dayDate`, re-render strip + events.
3. Append each pill to the strip.

#### 2e. `renderMobileDayEvents(date)`
1. Format `date` to `YYYY-MM-DD`.
2. Filter `allEvents` for that exact date.
3. Clear `#mobileDayEvents`.
4. If no events, show empty-state message.
5. For each event, build a card (same colour logic as desktop: green if ready, peach if not). Show program, venue, FOH/stage crew.
6. `onclick` → call existing `openEventModal(event)`.

#### 2f. Week navigation
- `mobilePrevWeek.onclick` → `currentDate.setDate(currentDate.getDate() - 7)` → `renderMobileCalendar()`.
- `mobileNextWeek.onclick` → `currentDate.setDate(currentDate.getDate() + 7)` → `renderMobileCalendar()`.
- (Optional) Long-press or double-tap week label to snap to today.

### 3. Backward compatibility / edge cases

- **Desktop**: Completely unchanged. The existing `#calendarGrid` and `renderCalendar()` continue to work.
- **Tablet (768 px+)**: Uses desktop month grid, which is acceptable.
- **Today button**: Keep the existing implicit "today" behaviour (today is highlighted). Add a small "Today" pill/button in the mobile week nav if the displayed week is not the current week.
- **Add Show navigation**: After adding a show, the app currently jumps to the show's month. On mobile, additionally set `selectedMobileDate` to the show date and re-render the mobile view so the user sees the new event immediately.
- **Orientation change**: The existing `resize` listener will handle switching between mobile week-view and desktop month-view.
- **Accessibility**: Ensure day pills have `role="button"`, `tabindex="0"`, and keyboard `Enter` support.

### 4. Testing checklist

- [ ] Mobile week view renders on page load (viewport < 768 px).
- [ ] Week nav arrows move forward/back by 7 days.
- [ ] Tapping a day pill updates the event list below.
- [ ] Event cards use correct green/peach logic.
- [ ] Tapping an event card opens the detail modal.
- [ ] Days with events show a coloured dot.
- [ ] Today is visually distinguished.
- [ ] Resizing browser to > 768 px switches to desktop month grid.
- [ ] Resizing back to < 768 px switches to mobile week view.
- [ ] After "Add Show", mobile view jumps to the new show's date.
- [ ] Empty days show a friendly "No shows" state.

## Rollback / risk mitigation

- The desktop month grid is untouched; only mobile CSS (`max-width: 767px`) and a new `#mobileCalendarView` container are added.
- If bugs are found, the mobile view can be quickly disabled by adding `display: none !important` to `#mobileCalendarView` and restoring visibility of the desktop grid on mobile.
- No backend or API changes are required.
