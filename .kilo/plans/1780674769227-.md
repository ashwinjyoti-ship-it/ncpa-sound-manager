# Mobile Calendar UX Redesign Plan

## Problem
On mobile (< 768 px), the full month calendar grid renders with 7 columns. Event cards are shrunk to `0.7rem` font, cells are only `80px` min-height, and the entire experience is cramped and hard to use. Users cannot easily read show details or tap the correct event. A single day can contain up to 8 events, making the grid completely unusable.

## Goal
Replace the mobile month-grid with a **week agenda view** that shows all events immediately at full readable size.

---

## Proposed UX — Week Agenda View

A vertically scrollable list of the entire week, similar to Google Calendar "Schedule" view and Outlook Agenda.

### 1. Week navigation bar (sticky)
`◀  1 – 7 Jun 2026  ▶`  
- Arrows shift by one week
- Long week labels are formatted as e.g. "26 May – 1 Jun 2026"
- A "Today" button appears when the displayed week is not the current week

### 2. Day sections
Each day is a section in the scrollable list:
- **Day header**: "Monday 1 Jun" (today gets a periwinkle accent dot or pill)
- **Event cards** (full-width, readable `text-sm` or `base`):
  - Program name (not truncated)
  - Venue
  - FOH / Stage crew (with icons)
  - Green or peach left-border (same logic as desktop)
  - Tapping opens the existing `openEventModal()`
- **Empty state**: if a day has no shows, show a compact "No shows" line so the user knows the day is empty (rather than it being missing)

### 3. Why this is the right choice
- **High-density days**: A day with 8 events is displayed as 8 full-size stacked cards — perfectly readable, no truncation.
- **Zero taps to see names**: Every show name is visible immediately upon scrolling to that day.
- **Natural scroll**: Users already know how to scroll a list; no new interaction patterns to learn.
- **Proven pattern**: Google Calendar mobile uses this as its default "Schedule" view.

## Files to modify

| File | What changes |
|---|---|
| `src/index.tsx` | Add a `#mobileCalendarView` container (hidden on `md:` and up) inside the existing `#calendarView`. Add CSS for the week-nav bar, day headers, and mobile event cards. Hide desktop grid on mobile. |
| `public/static/app.js` | Add `renderMobileCalendar()`, `renderMobileWeekEvents()`, `renderMobileEventCard()` functions. Detect mobile viewport on init and call mobile renderer instead of `renderCalendar()`. Wire prev/next week buttons and "Today" button. |

---

## State changes

- Reuse `currentDate` to track which **week** is being displayed.
- `currentDate` is anchored to the **Monday** of the displayed week.
- No additional state needed — the agenda view shows all 7 days at once.

## Detailed implementation steps

### 1. HTML / CSS — `src/index.tsx`

Inside `#calendarView`, add a new sibling container:

```html
<!-- Mobile week-agenda view (hidden on desktop) -->
<div id="mobileCalendarView" class="md:hidden">
  <!-- Sticky week nav -->
  <div class="sticky top-0 z-10 mb-3 px-1 py-2 flex justify-between items-center" style="background:rgba(255,255,255,0.85);backdrop-filter:blur(12px);-webkit-backdrop-filter:blur(12px);">
    <button id="mobilePrevWeek" class="btn-glass px-3 py-1.5 text-sm">
      <i class="fas fa-chevron-left"></i>
    </button>
    <div class="flex items-center gap-2">
      <span id="mobileWeekLabel" class="text-sm font-semibold text-gray-700">1 – 7 Jun 2026</span>
      <button id="mobileTodayBtn" class="hidden text-xs px-2 py-1 rounded-full" style="background:rgba(152,162,215,0.15);color:#465080;">Today</button>
    </div>
    <button id="mobileNextWeek" class="btn-glass px-3 py-1.5 text-sm">
      <i class="fas fa-chevron-right"></i>
    </button>
  </div>
  <!-- Week events list -->
  <div id="mobileWeekEvents" class="space-y-6 pb-6 px-1"></div>
</div>
```

Add CSS classes (inside existing `<style>` block, scoped to mobile via media query or Tailwind):
- `.mobile-day-header` — sticky within the scrollable container (stays visible while scrolling its events), shows day name + date, subtle bottom border.
- `.mobile-day-header.today` — accent left border or periwinkle text.
- `.mobile-event-card` — reuses `.event-card-green`/`.event-card-peach` but at full readable size (`text-sm` or `base`), padding `12px 16px`, generous gap between cards.
- `.mobile-no-shows` — muted text, centred, small padding.

Hide the desktop grid `#calendarGrid` and its sticky header on mobile by adding `hidden` class on mobile breakpoint (or using Tailwind `hidden md:grid` on the grid container).

### 2. JavaScript — `public/static/app.js`

#### 2a. Detect mobile
```js
function isMobileView() {
  return window.innerWidth < 768;
}
```
In `renderCurrentView()`:
```js
if (currentView === 'calendar') {
  if (isMobileView()) renderMobileCalendar();
  else renderCalendar();
}
```
Add a `resize` listener that switches between desktop and mobile renderers when crossing 768 px.

#### 2b. Week math helpers (Monday start)
```js
function getWeekStart(date) {
  const d = new Date(date);
  const day = d.getDay(); // 0 = Sun, 1 = Mon
  const diff = d.getDate() - day + (day === 0 ? -6 : 1);
  return new Date(d.setDate(diff));
}
function formatMobileDate(date) {
  const opts = { day: 'numeric', month: 'short' };
  return date.toLocaleDateString('en-GB', opts);
}
function formatMobileDayHeader(date) {
  const dayName = date.toLocaleDateString('en-GB', { weekday: 'long' });
  const dateStr = formatMobileDate(date);
  return `${dayName} ${dateStr}`;
}
```

#### 2c. `renderMobileCalendar()`
1. Compute `weekStart = getWeekStart(currentDate)`.
2. Compute `weekEnd = new Date(weekStart); weekEnd.setDate(weekEnd.getDate() + 6)`.
3. Update `#mobileWeekLabel` with formatted range: e.g. "1 – 7 Jun 2026" or "26 May – 1 Jun 2026".
4. Show/hide `#mobileTodayBtn` based on whether the current week includes today.
5. Call `renderMobileWeekEvents(weekStart, weekEnd)`.

#### 2d. `renderMobileWeekEvents(weekStart, weekEnd)`
1. Clear `#mobileWeekEvents`.
2. Pre-compute an `eventsByDate` map from `allEvents` (same logic as desktop `renderCalendar`).
3. Loop 0–6:
   - `dayDate = new Date(weekStart); dayDate.setDate(weekStart.getDate() + i)`
   - Format `dateStr = YYYY-MM-DD`
   - Create day section container.
   - Create day header: day name + date. Add `.today` class if `dayDate` is today.
   - Get `dayEvents = eventsByDate[dateStr] || []`.
   - If `dayEvents.length === 0`: append a compact "No shows" row.
   - Else: for each event, call `renderMobileEventCard(event)` and append.
   - Append day section to `#mobileWeekEvents`.

#### 2e. `renderMobileEventCard(event)`
Build a card element:
- Colour class: `event-card-green` if `requirements_updated && call_time && call_time.trim()`, else `event-card-peach`.
- Content:
  ```
  <div class="font-semibold text-sm">${event.program}</div>
  <div class="text-xs text-gray-600 mt-1"><i class="fas fa-map-marker-alt mr-1"></i>${displayVenue(event.venue)}</div>
  ${crewHtml}
  ```
- `crewHtml` uses same logic as desktop (prefer `foh_crew`/`stage_crew`, fall back to `crew`).
- `onclick` → `openEventModal(event)`.

#### 2f. Week navigation
- `mobilePrevWeek.onclick` → `currentDate.setDate(currentDate.getDate() - 7)` → `renderMobileCalendar()`.
- `mobileNextWeek.onclick` → `currentDate.setDate(currentDate.getDate() + 7)` → `renderMobileCalendar()`.
- `mobileTodayBtn.onclick` → `currentDate = getWeekStart(new Date())` → `renderMobileCalendar()`.

### 3. Backward compatibility / edge cases

- **Desktop**: Completely untouched. Existing `#calendarGrid` and `renderCalendar()` continue.
- **Tablet (768 px+)**: Uses desktop month grid.
- **Today button**: Only visible when the displayed week does NOT include today. Clicking it snaps back to the current week.
- **Add Show navigation**: After adding a show, `currentDate` is set to the show's month. On mobile, additionally snap `currentDate` to the Monday of that show's week so the user sees it immediately.
- **Orientation change**: Resize listener handles switching between mobile agenda and desktop grid.
- **High-density days**: Up to 8 events per day render as 8 stacked full-width cards — fully readable, no truncation.
- **Accessibility**: Event cards are already `<div>` elements with `onclick`; ensure they have `role="button"` and `tabindex="0"` for keyboard users.

- [ ] Mobile agenda view renders on page load (viewport < 768 px).

- [ ] Week label updates correctly (e.g. crossing month boundaries like "26 May – 1 Jun").
- [ ] Today button appears when not on current week; clicking snaps to current week.
- [ ] Each day section shows correct day name and date.
- [ ] Today is visually distinguished.
- [ ] Days with events show full-size readable cards.
- [ ] Days with 0 events show a compact "No shows" row.
- [ ] Days with 8 events show all 8 cards without truncation.
- [ ] Event cards use correct green/peach logic.
- [ ] Tapping an event card opens the detail modal.
- [ ] Resizing to > 768 px switches to desktop month grid.
- [ ] Resizing back to < 768 px switches to mobile agenda view.

## Rollback / risk mitigation

- Desktop month grid is untouched.
- Mobile view is wrapped in `#mobileCalendarView` with `class="md:hidden"`.
- If bugs are found, disable mobile view by adding `style="display:none !important"` to `#mobileCalendarView` and removing the `hidden` class from the desktop grid on mobile.
- No backend or API changes are required.
