### 2. Conflict Detection ✅

**What It Does:**
- Detects venue conflicts (same venue, same date)
- Detects crew conflicts (same crew assigned to multiple events on same date)
- Visual severity indicators (error = red, warning = yellow)

**How to Use:**
1. Click **"Conflicts"** button (red) in top navigation
2. System scans next 3 months automatically
3. Modal shows all conflicts with details
4. Review conflicting events side-by-side

**Technical Implementation:**
- Backend: `/api/conflicts/detect` and `/api/conflicts/event/:id`
- Algorithm: O(n²) comparison within date ranges
- Caching for performance

---

### 3. Bulk Assignment with Smart Suggestions ✅

**What It Does:**
- Select multiple events for bulk operations
- AI-powered crew suggestions based on historical data
- Confidence scores for each suggestion
- Bulk status changes
- Bulk export
- Bulk delete

**How to Use (Bulk Crew Assignment):**
1. Go to **Table View**
2. Check boxes next to events
3. Bulk action bar appears
4. Click **"Assign Crew"**
5. System shows suggestions: "Ashwin (85% confidence - worked 35 JBT shows)"
6. Click suggestion or type custom names
7. Click **"Assign to X Events"**

**Your Question Answered:**
> "How will you do bulk assignment when you don't know crew capability?"

**My Solution:** Pattern-Based Learning System
- Tracks historical assignments (venue → crew)
- Calculates confidence scores: `(assignments at venue / total venue events) × 100`
- Suggests crew automatically based on venue
- You confirm/modify before applying
- Gets smarter with more data

**Example:**
```
Venue: JBT
Suggestions:
- Ashwin (85% confidence - 35 past assignments)
- Naren (72% confidence - 28 past assignments)
- Sandeep (45% confidence - 12 past assignments)
```

**Technical Implementation:**
- Backend: `/api/crew/suggestions` (historical analysis)
- Backend: `/api/events/bulk-assign` (batch update)
- Frontend: Smart suggestion UI with confidence scores
- Database: `crew_assignment_history` table

### 6. Customized Export with Change Tracking ✅

**What It Does:**
- Exports with SHA-256 checksums for change detection
- Google Sheets compatible CSV format
- Tracks what changed since last export
- Includes all fields + metadata

**How to Use:**
1. Export events normally (existing button)
2. System generates checksum
3. Next export: checks if data changed
4. Shows warning if changes detected
5. Import CSV into Google Sheets
6. Update specific rows/cells
7. Re-export to sync changes

**Google Sheets Workflow:**
```
Day 1: Export → Import to Sheets
Day 2: Update crew for Event #123 in Sheets
Day 3: Export again → See change notification
Day 4: Import updated CSV → Event #123 crew synced
```

**Technical Implementation:**
- Backend: `/api/export/tracked` (with checksum generation)
- Backend: `/api/export/check-changes` (checksum comparison)
- Frontend: localStorage for last export tracking
- Format: CSV with quoted fields, proper escaping

## 📊 Technical Architecture

**Filtering:**
- `POST /api/events/filter` - Apply multi-criteria filters
- `GET /api/events/filter-options` - Get available filter values

**Conflict Detection:**
- `GET /api/conflicts/detect?from=DATE&to=DATE` - Find conflicts in date range

**Bulk Operations:**
